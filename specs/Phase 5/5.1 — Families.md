# Spec 5.1 — Families

## Goal
Family units: a father, a mother, and their children. Person detail shows their parents (family where they're a child) and their own family/families (where they're father or mother). A family detail page shows both parents and all children.

## Backend

### Family Model — `server/src/db/family.rs`

```rust
#[derive(Debug, Clone, Serialize, Deserialize, CandidType)]
pub struct Family {
    pub handle:        String,
    pub gramps_id:     String,
    pub father_handle: Option<String>,
    pub mother_handle: Option<String>,
    pub family_type:   String,   // "married" | "unmarried" | "civil_union" | "unknown"
    pub private:       bool,
    pub change_date:   i64,
    pub created_at:    i64,
}

#[derive(Debug, Clone, Serialize, Deserialize, CandidType)]
pub struct FamilyChild {
    pub family_handle: String,
    pub child_handle:  String,
    pub father_rel:    String,   // "birth" | "adopted" | "step" | "unknown"
    pub mother_rel:    String,
}

#[derive(Debug, Clone, Serialize, Deserialize, CandidType)]
pub struct FamilyInput {
    pub father_handle: Option<String>,
    pub mother_handle: Option<String>,
    pub family_type:   Option<String>,
    pub private:       Option<bool>,
}
```

Implement: `Family::create`, `Family::get`, `Family::update`, `Family::delete`, `Family::list`.

Also:
- `Family::add_child(family_handle, child_handle, father_rel, mother_rel)`
- `Family::remove_child(family_handle, child_handle)`
- `Family::children(family_handle) -> Vec<Person>` — joins with person table
- `Family::get_parent_families(person_handle) -> Vec<Family>` — families where person is a child
- `Family::get_own_families(person_handle) -> Vec<Family>` — families where person is father or mother

### Candid API

```rust
#[query]  fn list_families() -> Vec<Family>
#[query]  fn get_family(handle: String) -> Option<Family>
#[update] async fn create_family(input: FamilyInput) -> Option<Family>
#[update] fn update_family(handle: String, input: FamilyInput) -> Option<Family>
#[update] fn delete_family(handle: String) -> bool
#[update] fn add_child_to_family(family_handle: String, child_handle: String, father_rel: String, mother_rel: String) -> bool
#[update] fn remove_child_from_family(family_handle: String, child_handle: String) -> bool
#[query]  fn get_family_children(family_handle: String) -> Vec<Person>
#[query]  fn get_person_parent_families(person_handle: String) -> Vec<Family>
#[query]  fn get_person_own_families(person_handle: String) -> Vec<Family>
```

## Frontend

### Family detail page — `src/routes/families/$handle.tsx`

Display:
- Family type (Married, Unmarried, etc.)
- Father: name link → `/persons/$handle` (or "Unknown" if not set)
- Mother: name link → `/persons/$handle` (or "Unknown" if not set)
- Children: list of person name links
- "Edit family" and "Delete family" buttons

### Family list page — `src/routes/families/index.tsx`

Table: Father name | Mother name | # Children | Actions

### New family page — `src/routes/families/new.tsx`

Form: father (person picker — searchable dropdown or text handle input for now), mother (same), family_type select.

**Note:** A full person-picker is complex. For Phase 5, use a simple text input for handle — the user pastes the Gramps ID or handle. Add a person search dropdown in a later phase.

### Person detail page updates — `src/routes/persons/$handle.tsx`

Add two new sections:

**Parents section:**
- Fetch `get_person_parent_families(handle)`
- For each family: show "Father: [name]" and "Mother: [name]"

**Families section:**
- Fetch `get_person_own_families(handle)`
- For each family: show spouse name + link to family detail

Add "Families" link in nav.
