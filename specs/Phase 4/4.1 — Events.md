# Spec 4.1 — Events

## Goal
Add event support: a person can have a birth event and a death event (the two most common). Events have a date (free-text + sort value), an optional place (text for now, full Place entity in Phase 6), and a description. Birth/death show on the person detail page. Users can add/edit birth and death events directly from the person detail view.

## Scope (Phase 4)
- Event CRUD backend (Rust: `event` table)
- Link birth/death to person via `birth_ref_handle` / `death_ref_handle`
- `person_event_ref` table for the general person→event link
- Person detail page shows birth/death info
- Inline add/edit birth/death events (no separate event pages yet — keep it simple)

## Backend

### Event Model — `server/src/db/event.rs`

```rust
use serde::{Deserialize, Serialize};
use candid::CandidType;
use ic_rusqlite::with_connection;

#[derive(Debug, Clone, Serialize, Deserialize, CandidType)]
pub struct Event {
    pub handle:       String,
    pub gramps_id:    String,
    pub event_type:   String,   // "birth" | "death" | "marriage" | "baptism" | ...
    pub place_text:   Option<String>,  // free text for now (Phase 6 adds Place entity)
    pub date_sortval: Option<i64>,     // YYYYMMDD integer for sorting
    pub date_text:    Option<String>,  // human-readable: "15 Mar 1872", "Abt. 1900", etc.
    pub description:  String,
    pub private:      bool,
    pub change_date:  i64,
    pub created_at:   i64,
}

#[derive(Debug, Clone, Serialize, Deserialize, CandidType)]
pub struct EventInput {
    pub event_type:   String,
    pub place_text:   Option<String>,
    pub date_sortval: Option<i64>,
    pub date_text:    Option<String>,
    pub description:  Option<String>,
    pub private:      Option<bool>,
}
```

Implement `Event::create(handle, gramps_id, input)`, `Event::get(handle)`, `Event::update(handle, input)`, `Event::delete(handle)`.

**Note:** The `event` table uses `place_handle` (FK to place), but we don't have Place yet. Add a `place_text TEXT` column to the migration OR store place as free text in `description` for now. Simplest approach: add a migration `002_event_place_text.sql` that adds `ALTER TABLE event ADD COLUMN place_text TEXT;` — this lets the event store a place string without requiring the Place entity.

`set_birth_event` should:
1. Insert into `person_event_ref` (person_handle, event_handle, role="primary")

## Migration

Create `server/src/migrations/002_event_place_text.sql`:
```sql
ALTER TABLE event ADD COLUMN IF NOT EXISTS place_text TEXT;
```

Or if SQLite doesn't support `IF NOT EXISTS` on ALTER TABLE, just:
```sql
ALTER TABLE event ADD COLUMN place_text TEXT;
```

**Note:** SQLite doesn't support `IF NOT EXISTS` on ALTER TABLE. Use a simple `ALTER TABLE event ADD COLUMN place_text TEXT;` — ic-sql-migrate runs migrations in order and won't re-run 001 if it's already applied.
